# ADR 0001: Implement in Rust

- **Status:** accepted
- **Date:** 2026-11-08

## Context
The CA holds signing keys and parses attacker-supplied ASN.1 (CSRs, certificates). Most historic CA and TLS vulnerabilities are memory-safety bugs in exactly that parsing code. The service should also be a single, easy-to-deploy daemon.

## Decision
Rust (edition 2024), with:
- `rcgen` for building/signing certificates, CSRs and CRLs,
- `x509-parser` for parsing and signature verification,
- `aws-lc-rs` as the single crypto backend (rcgen, x509-parser `verify-aws`, rustls),
- `axum` + `tokio` + `axum-server` (rustls) for HTTP,
- `rusqlite` (bundled SQLite) for storage,
- `p12-keystore` and `pkcs8` for PKCS#12 and encrypted keys.

`unsafe_code = "forbid"` across the workspace; clippy `unwrap_used`/`expect_used` warnings in non-test code.

## Consequences
+ Memory safety in ASN.1 handling; one static binary per role; strong typing of policy/profiles.
+ aws-lc-rs is FIPS-capable if that's ever required.
− Smaller PKI ecosystem than OpenSSL/Go: OCSP and ACME server need more work (see roadmap).
− aws-lc-sys needs a C toolchain + CMake at build time.
